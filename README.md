# Вариант 29. Спавнер мобов в игре

Консольное приложение на C# демонстрирует **Flyweight (Приспособленец)** и **Factory Method (Фабричный метод)** на примере волн гоблинов, скелетов и драконов.

## Реализовано
- Спавн волны мобов трёх типов.
- Общие данные типа (модель, базовое здоровье, урон, внешний вид и поведение) хранятся в одном `MobArchetype`.
- Индивидуальные данные моба: ID, координаты и текущее здоровье.
- Для каждого типа есть отдельная фабрика; общий алгоритм создания находится в `MobFactory`.
- Демонстрируется повторное использование общих данных и независимость здоровья экземпляров.

## Структура
```text
Models/ Mob.cs, MobArchetype.cs
Patterns/ MobArchetypeFactory.cs, MobFactory.cs, GoblinFactory.cs, SkeletonFactory.cs, DragonFactory.cs, MobSpawner.cs
Program.cs
UML.puml
```

## Паттерны
**Flyweight.** `MobArchetypeFactory` кэширует по одному объекту общих характеристик для каждого типа. Координаты и текущее здоровье остаются в конкретном `Mob`.

**Factory Method.** Абстрактная `MobFactory` задаёт алгоритм создания, а `GoblinFactory`, `SkeletonFactory` и `DragonFactory` определяют конкретный тип. Для нового типа добавляются новый класс фабрики и его использование в сценарии.

## Запуск
Требуется .NET 8 SDK. В папке проекта выполните:
```bash
dotnet run
```

## Проверки в выводе
1. Общих объектов типов — 3; мобов создано 6.
2. `ReferenceEquals` для двух гоблинов — `True`.
3. Для гоблина и скелета — `True` при проверке, что объекты типов разные.
4. Урон первому гоблину не меняет здоровье второго.
